# 常见问题

## 需要安装 WebView2 或 .NET 吗？

不需要。0.31.12 起正式版使用 GPUI 原生界面，不依赖 WebView2；程序是 Rust 原生程序，也不需要 .NET 运行时。

## 不装 Quicker 能用吗？

能。下载便携包解压运行即可使用剪贴板历史、收藏、超级菜单和局域网功能。Quicker 只是安装 / 唤起入口之一；"收集Quicker步骤"、"剪贴板改变时触发自定义动作"和聚合搜索里的 Quicker 动作来源需要 Quicker。

## 应该下载 x64 还是 ARM64？

按 Windows 系统架构选择：Intel / AMD 电脑选 x64，Windows on ARM 电脑选 ARM64。详见 [安装与配置](install.md#选哪种架构)。

## 怎么看自己的版本？

主窗口 → **帮助** 里的"软件信息"页显示当前运行的版本。Quicker 安装版的程序在 `%LOCALAPPDATA%\Programs\ClipHostRust`。

## 便携包解压后打不开

- 确认**完整解压了整个目录**，运行的是目录里的 `cliphost-app.exe`，同目录的 DLL 都还在。
- 可用同名 `.SHA256SUMS.txt` 核对下载文件是否完整。
- 如果已经有一份（安装版或另一份便携版）在运行，新启动的这份不会再开一个，而是把已运行的那份窗口唤出来；看托盘是否已有图标。
- 仍然不行，按下一节收集诊断。

## 启动失败或闪退

1. 启动错误或程序崩溃（Rust panic）时会弹出原生错误框，显示原因、诊断日志位置和栈摘要；按 `Ctrl` + `C` 可复制内容。
2. 双击便携包里的 `Start-ClipHostDiagnostics.cmd`（Quicker 安装版的程序目录通常是 `%LOCALAPPDATA%\Programs\ClipHostRust`）。诊断结束后把提示的反馈 ZIP 和复现说明一起发送。
3. 诊断输出在 `%LOCALAPPDATA%\ClipHostRust\diagnostics`，**不会自动上传**；不采集剪贴板正文、历史 / 收藏数据库、账号凭据或完整配置，但日志里可能含本机路径，发送前可自行查看。
4. 程序日志在数据文件夹的 `logs` 子目录里。

已有 ClipHost 进程时，诊断只采集现况，不会重启或结束它。

## 开机自启后提示 `overflow when subtracting duration from instant` 并退出

部分电脑开机早期自启时可能出现此错误，**0.31.23 已修复**，请升级到 0.31.23 或更新版本。

## 杀毒软件（如卡巴斯基）报毒

0.31.15 起已移除文件对话框导航时向其它进程加载 DLL 的做法，并限制本地接口的浏览器访问来源；发布前会对原始 ZIP 做 Defender 扫描。但程序**尚未配置可信发布者代码签名**，也尚未取得卡巴斯基复测确认，不能保证所有安全软件都不再告警。请从 [eaclip Releases](https://github.com/ceastld/eaclip/releases) 或 Quicker 动作获取程序，并可用 SHA-256 核对。

## 升级会丢数据吗？

0.31.x 各版本都继续读取原有历史、收藏、配置及图片目录，不移动用户数据，也不会自动转换成实验中的新存储格式。图片显示缓存与原图分离，清理缓存不会删除原图。

## 数据存在哪里？怎么换位置？

见 [安装与配置 · 数据位置](install.md#数据位置)。更改位置不会自动迁移数据。

## 便携版和安装版能一起用吗？

不能同时运行两份，但两者共用同一份数据；开机自启指向最后启动的那份程序。详见 [安装与配置](install.md#便携包与-quicker-安装版能同时用吗)。

## 怎么卸载？

没有单独的卸载程序。先在设置里关闭"开机自启"和"使用 Win+V 打开剪贴板"，从托盘退出，再删除程序目录；需要时再删数据目录。完整步骤见 [安装与配置 · 卸载](install.md#卸载)。

## 提示"旧数据库格式不受支持"

请通过 [反馈仓库](https://github.com/QuickerHub/cea-action-issues/issues) 联系作者。作者可按需提供只读的结构采集脚本 `Get-ClipHostStorageSchema.cmd`：只读取表名和列名，不读取内容、不修改数据库。

## 快捷键没反应

- 确认 ClipHost 正在运行（系统托盘有图标）。
- 到 **设置 → 触发** / **设置 → 便捷粘贴** 查看该快捷键是否被留空，或是否提示与其它快捷键 / 软件冲突。
- `Win` + `V` 需要开启"使用 Win+V 打开剪贴板"并**重启 Windows 资源管理器**。
- 列表里的 `A` / `B` / `C`、`M` 等按键在当前版本不存在，见 [快捷键 · 当前版本没有的按键](hotkeys.md#当前版本没有的按键)。

## 暂停记录能定时吗？

不能。底栏"暂停"是开关，暂停后需要再点一次"继续记录"。

## 设备同步没有生效

0.31.26 起，打开 **设置 → 跨设备**，确认总开关及需要的文本 / 图片已开启，并确认两台电脑已在局域网中配对且在线。新版不再要求逐台配置发送 / 接收方向；升级时此前关闭的总开关会保留，需要时可在这里重新开启。

若重复条目来自多款同步工具，可只保留一套自动同步。新版可合并像素完全相同、仅 PNG 编码或标准附加信息不同的图片；图片本身被第三方改变时仍会保留新内容。

找不到设备时，检查两台电脑是否在同一局域网、对方是否开启互传，以及防火墙是否放行 ClipHost。

## 能和手机同步吗？

目前不能。当前正式版没有手机同步入口，也没有公开发布的手机客户端。

## 「剪贴板」和「剪贴板 n10」有什么区别？

根据源码仓库的产品划分：

| | 「剪贴板 n10」 | 「剪贴板」（稳定版）/「剪贴板 pre」 |
| --- | --- | --- |
| 产品线 | ClipHost 独立进程（本文档所述的 eaclip）。0.31.x 为 Rust + GPUI；更早的 0.30.x 为 .NET + WebView | legacy 0.8.x，运行在 Quicker 进程内的 WPF 插件 |
| 运行方式 | 单独的 `cliphost-app.exe`，托盘常驻，不装 Quicker 也能用 | 随 Quicker 运行 |
| 更新 | 持续更新，新功能都在这条线 | 独立维护、独立发版 |

建议：新用户使用「剪贴板 n10」（或 eaclip 便携包）。本文档只适用于「剪贴板 n10」/ eaclip。

> 待确认：动作库里「剪贴板」稳定版当前对应的具体版本与维护计划；它与「剪贴板 n10」能否同时开启、是否会共用同一份数据（n10 首次启动会自动沿用 `文档\Quicker\Ceastld` 等旧数据目录）。

## 旧版（0.30.x，.NET）报错怎么办？

0.30.x 是旧的 .NET + WebView 版本，已不再更新。例如 0.30.35 发布包缺少 `IntelliTools.Quicker.dll`，会报 `FileLoadException`（HRESULT `0x80131047`）导致子程序无法加载，0.30.36 已修复。遇到旧版问题，建议直接通过「剪贴板 n10」升级到 0.31.x。更多见 [已知问题 · 旧版](known-issues.md#旧版030x问题)。

## 和"BetterClip（Ctrl+Alt+V）"是什么关系？

早期有个 Rust 原型 betterclip（默认 `Ctrl` + `Alt` + `V`，数据目录 `BetterClipRs`），已废弃，和现在的 eaclip / ClipHost 不是同一个程序，快捷键和数据都不通用。
